# Rules for this hand-off (binding)

The repository is a native iOS 26 paint-by-numbers app. CLAUDE.md in your worktree describes the layout, conventions, Swift 6 strict-concurrency rules and the CI loop; read it first and follow it (MainActor default isolation in the app, `nonisolated` for pure helpers, `@concurrent` for CPU-heavy async work, MemberImportVisibility: every file imports every module whose members it touches, Liquid Glass UI, no dead code, no TODO litter, comments explain why).

- There is no Xcode here: code under App/ cannot be compiled locally; CI compiles it later. After editing any Swift file under App/, re-read the whole file and check every import, every actor-isolation boundary, every API name and signature against iOS 26 / Swift 6.2, and every call site of anything you renamed. When unsure of an API, grep the repo for existing usage and mirror it.
- PaintCore (Sources/, Tests/) builds and tests here in Docker: `tools/swift.sh build -c release --static-swift-stdlib` (the static pbn lands at .build/release/pbn and runs on the host) and `tools/swift.sh test`. Both must pass before you finish if you touched Sources/ or Tests/. The Docker daemon is running. "database is locked" means another build is using the same .build folder: wait and retry.
- Quality gate: `python3 tools/regression.py` (needs the release pbn; `--self-test` checks the rules). If your change alters pipeline output, run `python3 tools/regression.py --update --sheets /tmp/pbn-<task>/sheets`, look at the sheets with the Read tool, and commit tools/baseline/regression.json with the change. Do not change TemplateGenerator.pipelineVersion (it is 2 and unreleased; the orchestrator owns it).
- Evaluation photos: App/PaintByNumber/Resources/Samples/*.jpg and /home/user/paint-by-number/.claude/corpus/*.png (astronaut = a face, chelsea = a cat, coffee, rocket). `python3 tools/eval.py run <images> --out <dir> [-- --colors 24 --detail 0.5]`, then Read the PNG sheets.
- Work only inside your own worktree. Never modify /home/user/paint-by-number itself or any other worktree. Scratch output goes under /tmp/pbn-<task>/. Never commit .claude/, .build/, eval output or tools/node_modules.
- Git: commit on your worktree's branch, messages in the style of the existing history (imperative summary line, then a short body of what and why), each ending with exactly these two lines:
  Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
  Claude-Session: https://claude.ai/code/session_01MTn2gAxHRttKtxHnSDvkAb
  Never rebase, amend, reset or otherwise rewrite existing commits. Do not push. No pull requests. Finish with `git status --porcelain` empty.
- Quality bar: this app is meant to be flawless. No stubs, no partial wiring, no shortcuts. Every new behaviour gets a test (Swift Testing in Tests/PaintCoreTests for PaintCore; XCTest in App/PaintByNumberTests; UI tests in App/PaintByNumberUITests; a demo scenario in ci/scenarios.txt that calls DemoMode.markReady() for any screen worth a CI screenshot; demo code stays inside #if DEBUG). Keep CLAUDE.md accurate.
- The app branch is receiving compile fixes from CI in parallel. Keep your diff to what your task needs; do not reformat or refactor unrelated code, so merges stay clean.
- Your final message goes to the orchestrator, not the user: what you changed and why, test results (paste the summary lines), anything unresolved, and the head commit SHA.
