# Localization brief

GROUP localization — make every user-facing string localizable and keep it that way.

Current state (verified on the merged tree you are working on): the project has no string catalog; the Xcode project's knownRegions are en and Base, LOCALIZATION_PREFERS_STRING_CATALOGS is YES but nothing is extracted (no Xcode here). SwiftUI views mostly pass literals to Text/Button/Label (LocalizedStringKey, fine), but many strings are built as plain String and never reach localization: PaintingTime ("~40 min", "2 h 14 min"; Model/Artwork.swift), CreateError messages (Features/Create/CreateModel.swift), ArtworkExporter error messages (Export/ArtworkExports.swift), PDF labels "Color Key", "Reference", "areas" (Export/PDFExporter.swift), hand-built plurals in Features/Gallery/AppShellView.swift ("4 in progress · 2 finished"), toast strings passed as String (Features/Gallery/GalleryView.swift, ArtworkPaintingView.swift), recovery screen text (PaintingRecoveryView.swift), time-lapse export sheet (Features/Share/TimelapseExport.swift), tips (Features/Paint/PaintTips.swift), acknowledgements and About (Features/Settings/*), the photo peek control, and the accessibility strings in Features/Paint/PaintSpeech.swift and Model/ColorNameText.swift (those two already use String(localized:defaultValue:comment:) with explicit keys — keep that convention where it exists). The PaintCore package is a library and its strings (pbn CLI output, ColorName.english) stay untranslated.

Deliver:
1. App/PaintByNumber/Resources/Localizable.xcstrings, hand-authored in Xcode's string-catalog JSON (sourceLanguage en, version 1.0), holding EVERY user-facing string of the app target: SwiftUI literal keys exactly as written in code (the source string is the key), explicit keys with defaultValue where code uses String(localized:defaultValue:comment:), and plural forms as catalog variations (%lld with one/other) for every count ("%lld in progress", "%lld finished", "%lld areas", "%lld min", …). Give each entry a comment that tells a translator where it appears and what the placeholders are. Also App/PaintByNumber/Resources/InfoPlist.xcstrings for the usage descriptions and display name (the target sets them through INFOPLIST_KEY_* build settings; check how they must be keyed).
2. Convert every hard-coded user-facing String to localized API: String(localized:) / LocalizedStringResource, catalog plurals instead of hand-built ones, and Foundation formatters for numbers, percentages, dates and durations (Duration/Measurement/Date formatted styles; never concatenate numbers into words). Error types get LocalizedError conformance with localized descriptions. Accessibility labels/values/hints included. Keep string keys stable where UI tests reference them by label (check App/PaintByNumberUITests for labels and identifiers before changing any text).
3. Drift protection that runs on Linux CI: tools/strings_check.py scans the app sources for localizable literals (Text("…"), Label("…", …), Button("…", …), String(localized: "…"), LocalizedStringResource("…"), .navigationTitle("…"), confirmationDialog titles, accessibilityLabel(Text("…")), etc.: study the code to find the forms actually used) and fails when a literal is missing from the catalog or a catalog key is unused; wire it into the core CI job (.github/workflows/ci.yml) and document it in CLAUDE.md. It must pass on your final tree. Set SWIFT_EMIT_LOC_STRINGS = YES in the project so Xcode users can also extract.
4. Layout robustness: demo scenarios paint-long-text, gallery-long-text and settings-long-text that launch with doubled-length pseudo-localization (-NSDoubleLocalizedStrings YES via the demo's launch arguments; see ci/screenshots.sh and DemoMode for how scenarios are launched) so CI screenshots show every bar, badge, toast and sheet with strings twice as long; fix any truncation or overflow you can reason about (fixed-height bars, the progress badge's ViewThatFits, the completion bar, the palette caption).
5. Unit test in App/PaintByNumberTests (LocalizationTests.swift) that loads the catalog from the bundle, checks a sample of keys resolve, and that plural keys produce different strings for 1 and 2.
Do not add translations to other languages; the deliverable is a complete, verified source catalog and code that goes through it.
